# Design Document

## Overview

Esta funcionalidade adiciona a capacidade de administradores ativarem e desativarem reservas através da tabela de reservas administrativas. A implementação seguirá os padrões estabelecidos no projeto, utilizando React Query para gerenciamento de estado, shadcn/ui para componentes de interface, e respeitando a regra de negócio do prazo limite de 8:30 AM.

A solução será implementada como uma extensão do componente de ações da tabela existente (`table-actions.tsx`), adicionando novas opções ao menu dropdown e criando um novo hook de mutação para gerenciar a alteração de status.

## Architecture

### Component Structure

```
src/app/(dashboard)/reservas/_components/
├── all-reservations-table-columns.tsx (existente - sem alterações)
├── all-reservations-table-content.tsx (existente - sem alterações)
├── all-reservations-table.tsx (existente - sem alterações)
└── admin-table-actions.tsx (NOVO - ações administrativas)

src/_hooks/mutations/
└── use-toggle-reservation-status.ts (NOVO)

src/_services/
└── reservation.service.ts (ATUALIZAR - adicionar método toggleStatus)

src/_lib/
└── toast-messages.ts (ATUALIZAR - adicionar mensagens de reserva)
```

### Data Flow

1. **Usuário clica no menu dropdown** → Componente renderiza opções baseado no status atual e prazo limite
2. **Usuário seleciona ação** → Alert dialog é exibido solicitando confirmação
3. **Usuário confirma** → Hook de mutação é acionado
4. **Mutação executa** → Serviço faz chamada à API
5. **API responde** → Cache do React Query é invalidado e toast é exibido
6. **Tabela atualiza** → Dados são refetchados automaticamente

## Components and Interfaces

### AdminTableActions Component

Novo componente para ações administrativas na tabela de reservas.

```typescript
interface AdminTableActionsProps {
  reservation: Reservation;
}
```

**Responsabilidades:**

- Renderizar menu dropdown com opções contextuais
- Validar prazo limite usando `isBeforeCutoffTime`
- Exibir alert dialog de confirmação
- Gerenciar estados de loading durante mutação
- Exibir opção "Ver Detalhes" (reutilizando componente existente)
- Exibir "Cancelar Reserva" para reservas ativas
- Exibir "Reativar Reserva" para reservas canceladas

### useToggleReservationStatus Hook

Hook customizado para gerenciar a mutação de status de reserva.

```typescript
interface ToggleReservationStatusParams {
  id: string;
  newStatus: ReservationStatus;
}

function useToggleReservationStatus(): UseMutationResult<
  Reservation,
  Error,
  ToggleReservationStatusParams
>;
```

**Responsabilidades:**

- Executar mutação via ReservationService
- Invalidar queries relevantes após sucesso
- Exibir toasts de sucesso/erro
- Gerenciar estado de loading

### ReservationService Extension

Adicionar novo método ao serviço existente:

```typescript
async toggleStatus(id: string, status: ReservationStatus): Promise<Reservation>
```

## Correctness Properties

_A property is a characteristic or behavior that should hold true across all valid executions of a system-essentially, a formal statement about what the system should do. Properties serve as the bridge between human-readable specifications and machine-verifiable correctness guarantees._

### Property Reflection

Após análise do prework, identifiquei as seguintes redundâncias:

- Propriedades 1.2 e 1.3 podem ser combinadas em uma única propriedade sobre opções contextuais
- Propriedades 2.3 e 2.4 podem ser combinadas em uma propriedade sobre títulos corretos
- Propriedades 3.1, 3.2 e 3.5 podem ser combinadas em uma propriedade abrangente sobre validação de prazo

### Correctness Properties

Property 1: Opções contextuais baseadas em status
_For any_ reservation, the dropdown menu should display "Cancelar Reserva" when status is ACTIVE and "Reativar Reserva" when status is CANCELLED
**Validates: Requirements 1.2, 1.3**

Property 2: Desabilitação por prazo limite
_For any_ reservation, when the current time is at or after 8:30 AM on the reservation date, the status toggle options should be disabled
**Validates: Requirements 1.4, 1.5**

Property 3: Validação de prazo para datas futuras
_For any_ reservation with a future date (after today), the isBeforeCutoffTime function should return true, allowing status changes
**Validates: Requirements 3.1, 3.2, 3.5**

Property 4: Títulos corretos no dialog de confirmação
_For any_ status toggle action, the confirmation dialog should display the appropriate title: "Tem certeza que deseja cancelar esta reserva?" for cancellation or "Tem certeza que deseja reativar esta reserva?" for reactivation
**Validates: Requirements 2.3, 2.4**

## Error Handling

### API Errors

**Cenários de erro:**

1. **Reserva não encontrada (404)**: Exibir toast "Reserva não encontrada"
2. **Sem permissão (403)**: Exibir toast "Você não tem permissão para realizar esta ação"
3. **Prazo expirado (400)**: Exibir toast "Prazo para alterações encerrado"
4. **Erro de rede**: Exibir toast "Erro ao conectar com o servidor. Tente novamente"
5. **Erro genérico (500)**: Exibir toast "Erro ao alterar status da reserva"

**Estratégia:**

- Todos os erros são capturados no hook `useToggleReservationStatus`
- Mensagens de erro são extraídas da resposta da API quando disponíveis
- Fallback para mensagens genéricas quando erro não tem mensagem específica
- Toast de erro é sempre exibido ao usuário
- Estado de loading é resetado após erro

### Validação Client-Side

**Validações antes de chamar API:**

1. Verificar se usuário é admin (já validado pela rota)
2. Verificar prazo limite usando `isBeforeCutoffTime`
3. Verificar se reserva existe e tem ID válido

**Comportamento:**

- Validações falhas desabilitam botões de ação
- Mensagens explicativas são exibidas via tooltip ou texto desabilitado
- Nenhuma chamada à API é feita se validação falhar

   - Tag: `**Feature: admin-toggle-reservation-status, Property 2: Desabilitação por prazo limite**`

   - Verificar que isBeforeCutoffTime sempre retorna true

4. **Property 4: Títulos corretos no dialog de confirmação**
   - Gerar ações aleatórias (cancelar/reativar)
   - Verificar que título correto é exibido para cada ação
   - Tag: `**Feature: admin-toggle-reservation-status, Property 4: Títulos corretos no dialog de confirmação**`

## Implementation Notes

### API Endpoint

Assumindo que a API backend já possui ou precisará de um endpoint:

```
PUT /api/lunch-reservation/admin/reservations/{id}/status
Body: { "status": "ACTIVE" | "CANCELLED" }
```

Se o endpoint não existir, será necessário coordenar com o time de backend para criá-lo.

### Performance Considerations

1. **Invalidação de cache otimizada**: Invalidar apenas queries necessárias
2. **Debounce**: Não necessário, pois ação requer confirmação explícita
3. **Loading states**: Desabilitar botão durante mutação para evitar cliques duplos
4. **Optimistic updates**: Não recomendado devido à criticidade da operação

### Accessibility

1. **Keyboard navigation**: Menu dropdown deve ser navegável por teclado
2. **Screen readers**: Botões devem ter labels descritivos
3. **Focus management**: Após fechar dialog, foco deve retornar ao botão que o abriu
4. **ARIA labels**: Adicionar aria-label aos botões de ação

### Internationalization

Atualmente o projeto está em português. Todas as mensagens devem estar em português brasileiro:

- "Cancelar Reserva"
- "Reativar Reserva"
- "Tem certeza que deseja cancelar esta reserva?"
- "Tem certeza que deseja reativar esta reserva?"
- "Reserva cancelada com sucesso"
- "Reserva reativada com sucesso"
- "Prazo para alterações encerrado (até 8:30 AM do dia da refeição)"
